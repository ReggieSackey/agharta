# AGHARTA

**Agharta makes LLMs more creative — measurably.** Instead of asking a model once and hoping, it runs a *creative search*: multiple operators attack the problem from different angles, every idea carries provenance, evaluation is separated from the model's opinion of itself, and a learning loop shifts generation toward the strategies that actually produce results. Works with any major model provider, through a web dashboard or an [MCP](https://modelcontextprotocol.io) client.

> *Agharta* is named after the 1975 Miles Davis album — an hour of improvised, structured searching by a small ensemble. That's the spirit: improvisation with provenance.

---

## The problem it solves

Ask an LLM for ideas on a hard problem and you get the same predictable answers from every angle — one prompt, near-duplicates, no memory of what worked last time. Agharta treats idea generation as a **search problem** that surrounds the model with structure, instead of hoping the prompt alone produces creativity:

- **One prompt → near-duplicates.** A search → structurally different candidates.
- **Where did this idea come from?** Every idea carries its full ancestry: which strategy created it, from which parents, inspired by which source concepts.
- **Did it actually work?** Your real-world feedback is recorded separately from the AI's opinion of itself — and the system never confuses the two.

## The strategy: four operators, two learning loops

### Four ways to think

Every idea is generated by one of four **creative operators**, each a genuinely different causal strategy — not the same prompt wearing four hats:

| Operator | What it does |
| --- | --- |
| **Divergent** | Generates alternatives grounded in *distinct causal mechanisms* — the disciplined baseline |
| **Analogy** | Transfers mechanisms from a curated library of 32 cross-domain source concepts (each with provenance), sampling near/moderate/far matches and reasoning about what should and shouldn't transfer |
| **Inversion** | Takes a constraint, inverts or relaxes it, then *repairs* the result back toward the real hard constraints — recording what was inverted and whether it survived |
| **Recombination** | Fuses two genuinely distinct parent ideas, noting complementary mechanisms and incompatibilities |

After each generation: judge → deduplicate → keep the diverse and viable → optionally recombine into the next generation. Selection is explicitly a **heuristic** (quality proxy + distance to everything already selected), with a reserved slot for unusual-but-viable ideas so weird lineages aren't pruned just for being weird.

### Two loops that learn

**Loop 1 — which strategy deserves more budget?** Every idea permanently records its operator. Your outcomes (`shortlisted` → `attempted` → `succeeded`/`failed`) update per-operator, per-domain scorecards with honest uncertainty (Beta-Bernoulli estimates). A [Thompson sampler](https://en.wikipedia.org/wiki/Thompson_sampling) turns those into budget weights for the next run — with a guaranteed exploration floor (~10%) so nothing starves on thin evidence, and `unknown` outcomes never counted as failures. This isn't a display: **the next exploration actually runs with the updated weights.**

**Loop 2 — can the recipe itself improve?** The full strategy (prompts, operator weights, models, budgets) is a versioned snapshot. A **challenger** with exactly one change runs against the **champion** on the same fixed benchmark problems × multiple seeds, under matched budgets. A pre-declared gate decides — at least +10% on the primary metric with no regression on feasibility or diversity. A rejected challenger can *never* be promoted (the database refuses). An eligible one still requires a human click. Every promotion is audited: what changed, why, and with what evidence.

### Evidence honesty (the core design rule)

Three tiers of evidence are stored, labeled, and displayed separately — never merged:

1. **Automated proxy** — a rubric-anchored model judge scores originality/usefulness/feasibility (1–5) with uncertainty. Cheap, consistent, and *not* a real outcome.
2. **Human judgment** — your shortlists and rejections.
3. **Real outcomes** — attempted/succeeded/failed with optional evidence, marked `self_reported` unless verified.

When the system says an operator "works," you can always see how many real observations that claim rests on.

## What's in the box

- **Web dashboard** (Next.js + Convex): create problems, watch explorations run live, browse ideas with full provenance, explore the **lineage graph**, give feedback, and see operator rankings, challenger experiments, and promotion history — every number labeled with its evidence tier and sample size.
- **MCP server**: the same engine, callable from Cursor or any MCP client (`explore_problem`, `get_exploration`, `submit_idea_feedback`, `get_learning_summary`) over stdio.
- **Benchmark suite**: 14 fixed problem briefs across 6 domains (11 development + 3 holdout, never tuned on) with a reproducible runner comparing single-prompt vs repeated-sampling vs the full engine.

## Model-agnostic

The engine talks to one `ModelAdapter` interface. Swap providers via environment variables — no code changes:

| `AI_PROVIDER` | Package |
| --- | --- |
| `openai` | `@ai-sdk/openai` |
| `anthropic` | `@ai-sdk/anthropic` |
| `deepseek` | `@ai-sdk/deepseek` |
| `glm` (aliases: `zai`, `zhipu`) | `@ai-sdk/zai` |
| `openai-compatible` (Ollama, vLLM, Groq, OpenRouter, …) | `@ai-sdk/openai-compatible` |
| `fake` (deterministic, free — default) | built-in |

Generator and judge can be **different providers** (`CREATIVE_PROVIDER=deepseek`, `JUDGE_PROVIDER=glm`, …) so the judge isn't grading its own family's homework. Misconfiguration fails closed with a clear error — never a stuck run.

## Quickstart

Requires Node 22+ and [pnpm](https://pnpm.io). Everything runs free on the deterministic `fake` model; real providers need your own API key.

```bash
pnpm install

# 1. Convex backend (free dev deployment; runs `npx convex login` if needed)
npx convex dev

# 2. Web app
cp .env.example apps/web/.env.local   # fill in WorkOS values when you have them
pnpm build && pnpm dev:web            # http://localhost:3000
```

Without WorkOS credentials the login page shows a configuration notice and public pages still work. Full variable reference in [`.env.example`](.env.example).

**MCP client setup** — create a personal token in the dashboard (Settings → MCP tokens), then:

```bash
AGHARTA_CONVEX_HTTP_URL=https://<your-deployment>.convex.site \
AGHARTA_MCP_TOKEN=agt_... \
node apps/mcp/src/index.ts
```

Live-test scripts read `CONVEX_TEAM_SLUG` / `CONVEX_PROJECT_SLUG` (from your Convex dashboard URL) — set them in `.env.local`.

## Honest limitations

- **Real-model benchmarks haven't been run** — no API keys existed in the build environment. On the deterministic fake model, brute-force repetition actually beats the full engine on raw qualified-idea count (the engine trades volume for diversity and zero duplicates); whether that flips with a real model is exactly what the benchmark suite is for.
- Automated scores are a **proxy**, not ground truth; every UI surface labels them as such.
- The analogy library is curated and static (32 concepts); web retrieval is a future, SSRF-guarded addition.
- No model-weight training, no autonomous code rewriting, no unreviewed strategy promotion — by design.

## Security & privacy

Every Convex function verifies identity and workspace membership — a protected page is not an authorization boundary. MCP tokens are stored only as keyed HMAC-SHA256 hashes with constant-time comparison, shown once, revocable. Private ideas and outcomes stay workspace-scoped; nothing enters shared benchmarks without explicit opt-in. See [docs/SECURITY.md](docs/SECURITY.md).
